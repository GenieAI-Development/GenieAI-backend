# GenieAI Admin Data API Usage

This guide describes how to enter catalogue data through the GenieAI FastAPI
Admin API, import optional visual interpretations, build the retrieval indexes,
and verify catalogue readiness.

## 1. Start FastAPI

From the repository root, run:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Open the interactive Swagger interface:

```text
http://127.0.0.1:8000/docs
```

In Swagger, expand an endpoint, select **Try it out**, paste the JSON request,
and select **Execute**.

## 2. Import Products

### Endpoint

```http
POST /api/v1/admin/catalogue/products/import
```

### Request body

```json
{
  "category": "cakes",
  "product_ids": [
    "cake00KA001685",
    "cake00KA001686",
    "cake00KA001687"
  ]
}
```

### Field rules

| Field | Required | Format |
|---|---:|---|
| `category` | Yes | Lowercase category slug such as `cakes`, `flowers`, or `chocolates` |
| `product_ids` | Yes | Non-empty array of Kapruka product ID strings |

Surrounding whitespace is removed from product IDs, and duplicate IDs in the
same request are removed automatically.

The client only submits product IDs. For each ID, the backend calls
`kapruka_get_product`, validates the response, normalizes the supported fields,
and atomically updates the category catalogue.

### Successful response

```json
{
  "category": "cakes",
  "imported_count": 3,
  "failed_product_ids": []
}
```

### Partial-success response

```json
{
  "category": "cakes",
  "imported_count": 2,
  "failed_product_ids": [
    "cake00KA001687"
  ]
}
```

A failed or unknown product is reported in `failed_product_ids` and does not
create an incomplete catalogue record.

For a large catalogue such as 642 cakes, use batches of approximately 50–100
product IDs. Re-importing an existing product safely refreshes its stable fields
while preserving any existing visual interpretation.

### PowerShell example

```powershell
$body = @{
    category = "cakes"
    product_ids = @(
        "cake00KA001685"
        "cake00KA001686"
        "cake00KA001687"
    )
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/api/v1/admin/catalogue/products/import" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

### Generated canonical data

The endpoint creates or updates:

```text
data/catalogue/cakes.json
```

The stored format is:

```json
{
  "category": "cakes",
  "products": [
    {
      "product_id": "cake00KA001685",
      "name": "Springtime Birthday Ribbon Cake",
      "description": "Product description...",
      "vendor": "Kapruka Cakes",
      "weight_kg": 1.25,
      "price_snapshot_lkr": 5770,
      "is_active": true,
      "visual_interpretation": null,
      "visual_interpretation_model": null
    }
  ]
}
```

This canonical structure is generated by the backend. Do not submit full
product objects to the product-import endpoint.

The canonical catalogue does not store live stock, authoritative live price,
or image URLs.

## 3. Import Visual Interpretations

Products must exist in the category catalogue before their visual
interpretations can be imported.

### Endpoint

```http
POST /api/v1/admin/catalogue/visual-interpretations/import
```

### Request body

```json
{
  "category": "cakes",
  "model_name": "Qwen3.8-Max",
  "replace_existing": false,
  "items": [
    {
      "product_id": "cake00KA001685",
      "visual_interpretation": "A pastel birthday cake decorated with pink flowers and a ribbon design."
    },
    {
      "product_id": "cake00KA001686",
      "visual_interpretation": "A dark chocolate cake with gold decorations and a formal presentation."
    }
  ]
}
```

### Field rules

| Field | Required | Format |
|---|---:|---|
| `category` | Yes | Lowercase category slug |
| `model_name` | No | Non-empty model/provenance name when supplied |
| `replace_existing` | No | Boolean; defaults to `false` |
| `items` | Yes | Non-empty array of interpretation records |
| `items[].product_id` | Yes | Existing product ID in the requested category |
| `items[].visual_interpretation` | Yes | Non-empty interpretation text |

Use `replace_existing: false` for the safe default. Existing interpretations
are skipped. Use `true` only when existing interpretations should be replaced.

An unknown product ID rejects the request without modifying the catalogue.

### Successful response

```json
{
  "category": "cakes",
  "updated_count": 2,
  "skipped_count": 0
}
```

### PowerShell example

```powershell
$body = @{
    category = "cakes"
    model_name = "Qwen3.8-Max"
    replace_existing = $false
    items = @(
        @{
            product_id = "cake00KA001685"
            visual_interpretation = "A pastel floral birthday cake with a ribbon design."
        }
    )
} | ConvertTo-Json -Depth 4

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/api/v1/admin/catalogue/visual-interpretations/import" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

## 4. Build Search Indexes

Run this endpoint after product import and after any visual-interpretation
changes that should be reflected in Dense retrieval.

### Endpoint

```http
POST /api/v1/admin/catalogue/indexes/build
```

### Normal incremental build

```json
{
  "category": "cakes",
  "rebuild": false
}
```

This operation:

- generates embeddings for new or changed active products;
- skips products whose Dense `content_hash` has not changed;
- removes inactive products from the category Qdrant collection;
- rebuilds the complete category BM25 index;
- verifies index coverage.

### Forced rebuild

```json
{
  "category": "cakes",
  "rebuild": true
}
```

A forced rebuild recreates the category Qdrant contents, regenerates all active
Dense vectors, and rebuilds BM25. Normally, use `rebuild: false`.

### Response

```json
{
  "category": "cakes",
  "dense_upserted": 642,
  "dense_skipped": 0,
  "dense_removed": 0,
  "bm25_documents": 642,
  "ready": true
}
```

### PowerShell example

```powershell
$body = @{
    category = "cakes"
    rebuild = $false
} | ConvertTo-Json

Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/api/v1/admin/catalogue/indexes/build" `
    -Method Post `
    -ContentType "application/json" `
    -Body $body
```

The collection is created automatically in Qdrant Cloud using the name:

```text
kapruka_cakes
```

The default vector configuration is 1536 dimensions with Cosine distance.

## 5. Check Catalogue Health

### Endpoint

```http
GET /api/v1/admin/catalogue/{category}/health
```

For cakes:

```http
GET /api/v1/admin/catalogue/cakes/health
```

This endpoint has no request body.

### Response

```json
{
  "category": "cakes",
  "ready": true,
  "active_products": 642,
  "visual_interpretations_available": 642,
  "dense_not_indexed": 0,
  "bm25_not_indexed": 0
}
```

The category is ready for recommendations when:

```text
ready = true
dense_not_indexed = 0
bm25_not_indexed = 0
```

Visual interpretations are optional. A category can be ready when
`visual_interpretations_available` is lower than `active_products`.

### PowerShell example

```powershell
Invoke-RestMethod `
    -Uri "http://127.0.0.1:8000/api/v1/admin/catalogue/cakes/health" `
    -Method Get
```

## 6. Required Execution Order

```text
1. Import product IDs
2. Import optional visual interpretations
3. Build the Dense and BM25 indexes
4. Check catalogue health
5. Use POST /api/v1/recommendations
```

## 7. Required External Configuration

The product-import and index-build endpoints require the corresponding external
services to be configured in `.env`:

```dotenv
OPENAI_API_KEY=your-openai-key
QDRANT_URL=https://your-cluster.region.cloud.qdrant.io:6333
QDRANT_API_KEY=your-qdrant-cloud-api-key
KAPRUKA_MCP_URL=https://mcp.kapruka.com/mcp
```

Keep `.env` private and never commit API keys.
